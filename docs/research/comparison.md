**准确性声明**：下表只陈述各项目公开文档中的常见事实，细节以各项目官方规范为准；如发现偏差请提 PR 修正。状态行标注依据来源为"公开文档，未逐一复核"。

## 与各方案的关键分歧

**与 Bitcoin 的分歧**：不接受"固定总量 + 灭失即永久退出"的组合；不接受"奖励必然衰减至零"；不接受"能耗无上界"。分歧点是**是否承认这些是必须被调节的变量**，而不是否认比特币的历史价值。

**与 Ethereum 的分歧**：不采用账户模型与通用 VM（至少不在主链）；不认为状态膨胀可以用"更多二层"无限外包。分歧点是**主链应该多薄**。

**与 Zcash / Monero 的分歧**：不接受"默认全遮蔽"或"承诺绝对匿名"。HEN 的隐私目标是降低**未授权**关联，同时保留可验证的披露路径。分歧点是**隐私是默认值还是可选项**。

**与 Tezos 的分歧**：不接受"治理本身在链上按权重计票"。HEN 的参数自动调节是有界的工程机制，机制变更仍是公开论证，不是投票。分歧点是**治理是投票还是论证**。

## 本项目最可能的失败模式

按概率从高到低（主观判断，欢迎反驳）：

1. **机制堆叠**：六个创新同时上线，任一未验证即全盘失效——因此路线图把仿真放在原型之前，并设"失败信号"。
2. **权重制的路径依赖**：若 Q3 无法解决，履历权重应被砍掉，退回"抽签 + 成本锚"。
3. **隐私与合规的夹缝**：既不够隐私也不够合规，两头不讨好。
4. **无人接手**：文档再完整也不等于有人愿意实现。这是最现实的失败模式，`docs/handover/` 的存在就是为了降低它的概率。
