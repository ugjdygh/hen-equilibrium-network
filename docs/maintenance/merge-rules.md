# 合并规则 / Merge Rules

操作层规则。原则层见 `GOVERNANCE.md`，评审流程见 `docs/review/process.md`。冲突时以 `GOVERNANCE.md` 为准。

---

## 1. 按内容分类的合并门槛

| 内容 | 门槛 | 合并人 |
|---|---|---|
| README、术语、翻译、排版、勘误 | 1 名维护者 | 维护者 |
| 白皮书、协议草稿、仿真计划、测试用例 | 1 名维护者 + 1 名无关贡献者复核 | 维护者 |
| 机制语义变更 | RFC 收敛 + 决策记录（ADR） | 维护者（须有两名在场） |
| 代码实现（未来） | 代码评审 + 测试通过 | 实现维护者 |
| 安全相关实现 | 标注"未审计" + 独立审计评估 | 实现维护者 |
| 生态链接收录 | 满足 `docs/ecosystem/implementations.md` 最低门槛 | 维护者 |

## 2. 标签

| 标签 | 用于 |
|---|---|
| `docs` | 文档修订 |
| `translation` | 翻译 |
| `spec` | 协议规范 |
| `simulation` | 仿真调整 |
| `security` | 安全说明 |
| `implementation` | 社区实现 |
| `archived` | 归档 / 暂停 |
| `out-of-scope` | 价格、代币、募资、拉人 |
| `needs-repro` | 缺少可复现依据 |
| `needs-review` | 等待无关贡献者复核 |

## 3. PR 检查项

- [ ] 标题是祈使句，说明改了什么
- [ ] 描述里写了"为什么"，不只是"改了什么"
- [ ] 影响范围已标注（docs / spec / sim / impl / security）
- [ ] 关联了 issue 或 RFC（机制类必须有）
- [ ] 更新了 `CHANGELOG.md`
- [ ] 若推翻了白皮书某处，白皮书同一 PR 内已改
- [ ] 未引入代币、募资、价格、拉人内容

## 4. 冲突与分歧处理

1. 技术分歧 → 回到 RFC，不靠反复改动 PR 决胜负。
2. 两名维护者意见相反 → 保留双方理由，进入 `docs/review/decisions.md` 的"未决"区，不强行合并。
3. 无法收敛 → 允许分叉（`GOVERNANCE.md` §6），不在主仓库里长期拉锯。

## 5. 禁止的合并

- 引入任何管理员覆盖、跳过校验、后门参数的改动。
- 引入代币发行、兑换、定价、募资能力的改动。
- 把"未审计"改为"已审计"而没有审计报告支撑的改动。
- 删除历史决策、异议记录、已归档条目的改动（可以标注 `Superseded`，不能删除）。

## 6. 版本与发布

- 文档类修订：`vX.Y.Z` 中 Y 递增（如 v0.3.0 → v0.4.0）。
- 纯勘误、路径修正：Z 递增。
- 每次发布在 `CHANGELOG.md` 顶部加条目，含变更、理由、反对意见、待确认项。

## 7. 提交信息

```
<area>: <imperative summary>

why: <为什么必须改>
scope: docs | spec | sim | impl | security
refs: #issue / RFC 编号
```
