# 消息流草案 / Message Flow (draft)

**Status: `Draft`（非规范性）**。不定义传输协议，只定义"谁在什么条件下把什么发给谁"。

见白皮书 §4。网络层实现留待阶段 2。此文件用于让不同实现先对齐**消息类别与责任边界**。

---

## 1. 消息类别

| 类别 | 发送方 | 接收方 | 内容 | 是否可丢弃 |
|---|---|---|---|---|
| `TX_ANNOUNCE` | 用户节点 | 验证节点 | 交易哈希 + 完整交易（或仅哈希+按需索取） | 可（延迟重发） |
| `TX_REQUEST` | 验证节点 | 用户/验证节点 | 交易哈希列表 | 可 |
| `BLOCK_ANNOUNCE` | 共识节点 | 全网 | 区块头 + 高度 | 不可（丢失导致同步落后） |
| `BLOCK_REQUEST` | 任意节点 | 共识/验证节点 | 高度或哈希 | 可 |
| `STATE_SYNC` | 任意节点 | 任意节点 | 状态/头链范围 | 可（可重试） |
| `PEER_EXCHANGE` | 任意节点 | 任意节点 | 候选对等地址 | 可 |
| `FEE_HINT` | 验证节点 | 用户节点 | 费率区间估计 | 可 |
| `ALERT` | 任意节点 | 全网 | 检测到的分叉/异常（**非共识信号**） | 可 |

## 2. 规则

- **哈希优先**：公告只传哈希与元数据，完整数据按需索取，避免带宽被重复广播吃掉。
- **去重**：同一哈希在滑动窗口内只处理一次；窗口参数需可配置且有上界。
- **分层职责**：L0 只广播自身交易；L1 承担过滤与转发；L2 承担区块公告与状态维护。
- **不放大**：单个来源的重复广播不得导致网络流量线性增长（对应 TC-NW-02）。
- **不可信输入**：任何消息在通过校验前不得改变本地状态；`ALERT` 尤其不得作为链选择依据。

## 3. 待定项

1. 传播是否采用延迟转发以降低来源可观测性；代价是延迟上升（需量化，见 Q6/Q8 的间接影响）。
2. 批次中继的批次大小与延迟权衡。
3. 是否区分"验证节点专用"与"用户节点专用"通道，以及由此产生的观测点集中问题。
4. 状态同步的裁剪策略（裁剪后如何保证新节点仍能验证历史）。

## 4. 隐私注意

L1 验证节点天然能看到"谁先广播了什么"。这不构成匿名失败，但属于**元数据暴露**，须在白皮书 §8.3 的边界清单里明确列出，不得声称"网络层已隐私化"。
