# 审核清单 / Review Checklist

两张清单：**发布前**（每次公开推送文档时）与**机制变更评审**（每个 RFC）。

---

## A. 发布前清单

- [ ] 全文搜索旧名残留：`Steady Ledger`、`地平线`、`horizon-equilibrium-network`（应只剩对照表与沿革表）
- [ ] 全文搜索"币""代币""token""coin"（应只剩"不得使用/token governance 的否定表述"）
- [ ] 全文无"承诺、保证、必定、上线时间表"类措辞
- [ ] 全文无对话残留（"需要我……吗？""以下是为你生成"）
- [ ] 所有内部链接路径存在（`docs/` 下逐条点开）
- [ ] 版本号一致：README、白皮书、CITATION.cff、CHANGELOG 头部
- [ ] `CHANGELOG.md` 已记录本次改动，含理由
- [ ] `DISCLAIMER.md` 与白皮书 §12 表述一致（不发行、不募资、不运营）
- [ ] 作者角色表述一致（不牵头、不开发、不运营、不背书）
- [ ] 参考文献每条可独立核验
- [ ] 图表 SVG 可在浏览器打开（无乱码、无越界）
- [ ] 示例脚本可运行（`python3 examples/sim/incentive_sim.py`）
- [ ] 状态标签与实际阶段一致（`Draft` / Stage 0）

## B. 机制变更评审清单

- [ ] 提案说明了**代价**，不只写收益（对照 `docs/research/tradeoffs.md`）
- [ ] 触及原则优先级时，说明为什么可以例外
- [ ] 是否触碰 §12 合规边界（是 → 直接拒绝）
- [ ] 是否引入"可购买/可转让/可继承"的权重或席位
- [ ] 是否引入"条件失败后降级为可花费"的路径
- [ ] 是否引入未定义字段/标志位被忽略的行为
- [ ] 是否有可回滚路径或兼容窗口
- [ ] 是否给了可复算的验证方式（脚本、参数、反例）
- [ ] 是否更新 `docs/research/tradeoffs.md` 与 `docs/research/open-questions.md` 对应条目
- [ ] 是否有一名无关贡献者复核

## C. 交接清单（写给接手人）

- [ ] 模块卡片的六个字段都填了（规范/测试/仿真/问题/安全注意/验收）
- [ ] 已知坑写成文字，不只留在代码里
- [ ] 未实现项明确标注"未实现"，不用"待优化"含糊
- [ ] 状态标签正确（含"未审计"）

---

**用法**：A 每次发布；B 每个 RFC；C 每次交接。三项都不通过就不合并，不找理由例外。
