# 测试用例 / Test Cases

**性质**：设计级用例，不是可执行测试。每个实现应把这里的编号映射到自己的测试函数，并回填"通过/失败/未实现"。

**原则**：优先覆盖**失败路径**。一个协议死在"正常情况都对、异常情况没测"上。

格式：`编号 | 场景 | 预期 | 依据`

---

## TC-TX 交易（12）

| 编号 | 场景 | 预期 | 依据 |
|---|---|---|---|
| TX-01 | 单输入单输出，签名正确 | 接受 | §5.2 |
| TX-02 | 引用不存在的输出 | 拒绝 `INPUT_MISSING` | A1 |
| TX-03 | 重复花费同一输出（双花） | 第二笔拒绝 | A1 |
| TX-04 | 签名与交易哈希不符 | 拒绝 `SIG_INVALID` | A2 |
| TX-05 | 输入 < 输出 + 手续费 | 拒绝 `VALUE_MISMATCH` | A3 |
| TX-06 | 零金额输出 | 按规则集判定；默认拒绝并记录 | A3 |
| TX-07 | 遮蔽金额但范围证明成立 | 接受 | A4 |
| TX-08 | 遮蔽金额且范围证明被篡改 | 拒绝 `SHIELD_INVALID` | A4 |
| TX-09 | 未知条件类型 | 拒绝 `UNDEFINED_FIELD` | A6 |
| TX-10 | 未定义扩展标志位 | 拒绝 `UNDEFINED_FLAG` | A6 |
| TX-11 | 脚本资源超上界 | 拒绝 `SCRIPT_TOO_COSTLY` | A7 |
| TX-12 | 条件未满足（时间未到） | 输出保持锁定，交易本身可被接受但不改变可花费状态 | A5 |

## TC-NW 消息流（5）

| 编号 | 场景 | 预期 |
|---|---|---|

## TC-VF 验证流（5）

| 编号 | 场景 | 预期 |
|---|---|---|
| VF-01 | 校验顺序 | 先廉价后昂贵（格式→签名→脚本→状态） |
| VF-02 | 任一阶段失败 | 短路返回，不做后续计算 |
| VF-03 | 存在"跳过校验"开关 | 不存在，且不可配置 |
| VF-04 | 校验结果可复算 | 两节点对同一交易给出相同理由码 |
| VF-05 | 恶意构造的超大字段 | 在解析阶段被拒，不进入深层校验 |

## TC-LV 轻节点（5）

|---|---|---|

## TC-CN 共识节点（6）

## TC-DA 难度调节（8）

| 编号 | 场景 | 预期 |
|---|---|---|
| DA-01 | 算力突增 2 倍 | 难度上调，但单步不越上限 |
| DA-02 | 算力骤降 70% | 缓释难度，不出块停滞 |
| DA-03 | 交易池长期积压 | 按规则响应，不越界 |
| DA-04 | 连续同向调整达上限 | 触发熔断 `FROZEN` |
| DA-05 | 测量延迟 2 个周期 | 不出现无界振荡（Q6） |
| DA-06 | 输入被污染（伪造算力估计） | 钳制生效，损害有上界 |
| DA-07 | 相同输入两次计算 | 输出完全一致（无本地随机） |
| DA-08 | 参数越界输入 | `CLAMPED` 并记录 |
