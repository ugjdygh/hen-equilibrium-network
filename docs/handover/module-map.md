## 3. 依赖关系

```
交易结构 ─┬─> 默克尔树 ─> 区块头 ─> 共识节点
          ├─> 交易池 ─> 轻量验证节点
          ├─> 条件交易
          └─> 隐私遮蔽（依赖密码学选型，见 Q5）
难度调节 ──> 共识节点 ──> 稳态激励（依赖出块统计）
消息流 ──> 验证流 ──> 交易池
```

**实现顺序建议**：交易结构 → 默克尔树 → 区块头 → 交易池 → 验证流 → 难度调节 → 共识 → 激励 → 条件交易 → 隐私。隐私放最后，因为它会改动前面所有字段的编码假设。

## 4. 三个"最容易被做错"的地方

1. **条件失败降级。** 最容易写成"超时后可被任何人花费"。这是资金损失的第一大来源，必须 fail-closed。
2. **未定义标志位。** 实现里最省事的写法是"未知位忽略"。这会把兼容机制变成绕过机制，必须视为无效。
3. **难度调节的测量延迟。** 实现时常把延迟当 0 处理，仿真里"很稳"，实网里震荡（Q6）。

## 5. 交接时必附材料

新认领人接手一个模块时，交出的材料至少包含：规范位置、测试用例、仿真脚本、已知未解问题、你自己踩过的坑（写成文字，不要只留代码）。
