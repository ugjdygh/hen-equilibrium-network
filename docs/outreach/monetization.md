# How this project makes money

Short answer: **it does not, and it is not meant to.** This page exists because the question gets asked, and a vague answer invites people to assume a hidden plan.

## 1. Revenue from the repository itself: zero

| Possible channel | Status | Why |
|---|---|---|
| Token or allocation | none, ever | would end the research framing and make the author an issuer |
| Sponsorship / donation address | refused | `ROADMAP.md` stage 0 declines funds in any form, including sponsorship and paid consultation |
| Paid tier, course, membership | none | no product exists to sell |
| Advertising, affiliate links | none | nothing here is for sale, so there is nothing to promote |
| Licensing fees | impossible | MIT is free and irrevocable; no one owes the author anything |
| Selling stars, accounts, placements | prohibited | buying engagement is the one thing `docs/outreach/growth.md` rules out first |

There is no treasury, no address, no invoice and no entity to receive money. Anyone claiming to collect on the project's behalf is not doing so.

## 2. What it does produce, and what that is worth

- **Reputation**: a frozen, timestamped, citable record of a design and of its open problems. Non-transferable, non-monetisable directly.
- **Artifacts others can use**: the acceptance suite, the simulations, the module map, the handover pack.
- **Optionality**: evidence that the author can frame a mechanism and state its limits, which is the only thing that makes paid work plausible later — and that paid work is a *different* activity, not this one.

## 3. Adjacent work that can legitimately be paid (not this repository)

All of these are services or grants, priced in fiat, invoiced by a real person or entity. None of them can be done anonymously, and none of them touch the repository's name as a product.

| Activity | Typical range (indicative) | What it inherits from the repo |
|---|---|---|
| Design / mechanism review for another team | USD 80–250 per hour | the review habit and the simulation scripts |
| Writing or translating protocol documentation | USD 0.08–0.25 per word, or per project | the English/Chinese editions |
| Independent test-suite authoring | USD 1k–5k per suite | the 86 acceptance cases |
| Research grant or fellowship (public or academic) | USD 5k–60k per grant | the published record and open questions |
| Conference talk / workshop | honoraria, often travel only | the frozen whitepaper |

Two rules if any of these become real: **never invoice under this project's name**, and **never let the payer describe the payment as support for "the HEN project"** — that is sponsorship by another route.

## 4. What would break the "no revenue" stance

Any of the following makes every boundary document false, and each is visible from outside:

1. a token, allocation, airdrop or genesis share in the author's control;
2. a sponsorship, grant or donation received *for this repository* rather than for a service;
3. a paid "advisory" seat in an implementation of this design;
4. paid promotion, listing or review of anything;
5. an entity, foundation or company formed to hold value on the project's behalf.

## 5. The honest summary

This project is a cost, not a revenue line: it consumes time and returns reputation and artifacts. If the goal is income, the income comes from **work done for someone else** — review, writing, testing, grants — and that work is legitimate precisely because it is not this repository.

If someone wants a project that earns, the requirements are different at the first line: a named entity, a product, a licence that is not MIT, and a compliance posture appropriate to whatever is being sold. That is a different project, and this page does not pretend otherwise.
